## 8. Technical SEO specification

- Keep one canonical HTTPS host and permanently redirect every alternative host/protocol.
- Sitemap: include only canonical, indexable public pages; exclude booking confirmation, accounts, admin, query states and private records.
- Robots: allow public assets/pages, but use authentication or `noindex` for private areas; robots blocking is not a privacy control.
- Canonicals: self-reference normal pages; never canonicalize genuinely unique branch pages to the homepage.
- Status codes: deleted room/page with replacement → 301; no replacement → 410/404; never soft-404 to homepage.
- Structured data: `LodgingBusiness`/appropriate `LocalBusiness` per eligible branch, `HotelRoom` or `Product` only where properties are accurate, `BreadcrumbList`, `Article` for editorial content and visible `FAQPage` only when eligible and genuinely useful. Follow [Google’s LocalBusiness documentation](https://developers.google.com/search/docs/appearance/structured-data/local-business).
- Performance targets at the 75th percentile: LCP ≤2.5 seconds, INP ≤200 ms, CLS ≤0.1. These are Google’s [Core Web Vitals thresholds](https://web.dev/articles/defining-core-web-vitals-thresholds?authuser=1&hl=en); measure real field data, not assumptions.
- Images: responsive sizes, width/height, WebP/AVIF where useful, meaningful alt text for informative photos and empty alt for decorative images.
- Internationalization: add Urdu only with complete translated pages and reciprocal `hreflang`; never machine-create thin variants.
- Security/trust: no booking details in indexable URLs; protect confirmation routes; redact personal data from analytics.
